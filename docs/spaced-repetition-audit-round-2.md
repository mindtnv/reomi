# Интервальное обучение: второй аудит, 120 крупных пунктов

Дата: 19 сентября 2026. Основание: текущее рабочее дерево после первого прохода, включая его незакоммиченные изменения. Это **дополнительный backlog**, а не повтор [81 закрытого пункта](../openspec/changes/archive/2026-09-22-polish-spaced-repetition/tasks.md) и не утверждение о 120 найденных багах. Аудит первоначально не менял код. Текущий статус реализации отражают чекбоксы и [журнал результатов](spaced-repetition-round-2-progress.md).

Каждый пункт — самостоятельный результат для пользователя или сохранности его данных. Исправление должно включать только необходимую реализацию и проверку указанного сценария. Новые контракты API, модели данных и продуктовые возможности сначала оформляются через OpenSpec; обычные исправления проходят напрямую. Общие зависимости можно реализовать один раз, но нельзя закрывать зависимые пункты без проверки их собственного результата.

Обозначения основания:

- **R** — поведение воспроизведено вызовом действующих функций. Не обязательно нарушение уже принятого контракта: иногда это подтверждённое ограничение.
- **K** — конкретное поведение установлено чтением реализации; интеграционное воспроизведение ещё необходимо.
- **V** — риск или гипотеза: сначала воспроизвести, затем исправлять только при подтверждении.
- **P** — предлагаемая возможность или изменение принятого поведения. Отсутствие возможности само по себе не считается багом.

Приоритеты: **P0** — потеря данных/тихая подмена содержимого, затронутый путь следует исправить или временно закрыть перед выпуском; **P1** — существенное нарушение основного сценария; **P2** — следующий продуктовый проход; **P3** — развитие после обратной связи. Приоритет — оценка этого аудита, не уже согласованный срок.

Итого: **8 воспроизведённых ограничений/дефектов, 41 находка по реализации, 17 рисков для проверки, 54 продуктовых предложения**. По приоритетам: **4 P0, 56 P1, 59 P2, 1 P3**. Наличие P1 у предложения означает важность при принятии соответствующего контракта, а не автоматически обязательную новую функцию перед завтрашним выпуском.

## Очередь перед выпуском

1. Сначала R2-001, R2-013, R2-015, R2-097: сохранность исходного текста, полей, идентичности карточек и истории. Для редактирования структуры типа временное ограничение опасных операций допустимо как небольшой первый фикс.
2. Затем R2-002, R2-003, R2-014, R2-020, R2-026, R2-028, R2-050, R2-085, R2-088: поиск/отображение, согласованность типов, конфликты редактирования, неопределённый результат оценки и достоверность статистики.
3. До обещания надёжной работы на нескольких устройствах проверить R2-099–R2-102. До массового открытия регистрации отрепетировать R2-108 и измерить R2-119.
4. Остальные пункты выполнять по приоритету и подтверждённой потребности. Номера группируют области, а не предписывают сначала реализовать все новые функции первой группы.

Не включены: собственный алгоритм FSRS, микросервисы, Redis ради этой доработки, CRDT, событийная шина, автоматическая оптимизация весов без накопленной истории, полноценная офлайн-синхронизация. Для восстановления сессии достаточно небольшого локального checkpoint и сверки с сервером; это не разрешение оценивать карточки офлайн.

## A. Содержимое и поведение типов карточек

- [x] **R2-001 · P0 · R — Сохранять Markdown без потери текста.** Серверный HTML sanitizer удаляет `<T>` из `Array<T>` и HTML-примеры даже внутри fenced code. Основание: [E01], проба R-A. **Готово:** исходные Markdown-поля проходят save → reload побайтно для этих примеров; опасная разметка остаётся инертной при отображении, существующие проверки XSS проходят.

- [x] **R2-002 · P1 · R — Извлекать поисковый текст с учётом контекста Markdown.** Независимо от сохранения, `generateCards` превращает код `Array<T>` в поисковое `Array`; пустой alt у Markdown-картинки оставляет в индексе служебный URL. Основание: [E02], R-B. **Готово:** код ищется по содержимому, медиа-токены не засоряют текст; предусмотрено пересоздание старых производных render/index данных.

- [x] **R2-003 · P1 · R — Не исполнять математическую разметку внутри кода.** В inline/fenced code `\(x\)` превращается в KaTeX. Основание: [E04], R-D. **Готово:** буквальные примеры синтаксиса сохраняются в code, а формулы вне code продолжают работать во всех местах показа карточки.

- [x] **R2-004 · P2 · R — Сделать номера cloze самостоятельными карточками.** Сейчас c1 и c2 дают одну карточку с двумя скрытыми ответами. Это расширение текущей модели, а не небольшая правка регулярного выражения. Основание: [E02], [E03], R-C. **Готово:** разные номера имеют отдельное расписание; одинаковый номер объединяет пропуски; миграция явно сохраняет существующую историю. Ориентир: [cloze в Anki](https://docs.ankiweb.net/editing.html#cloze-deletion).

- [x] **R2-005 · P1 · R — Разобрать cloze с подсказками и фигурными скобками.** `answer::hint` раскрывается целиком, формулы со скобками и вложенные конструкции повреждают разбор. Основание: [E03], R-C. **Готово:** поддерживаемая грамматика однозначна; hint отделён от ответа; неподдерживаемая вложенность вызывает ошибку автора, а не битый вопрос. Ориентир: [синтаксис cloze](https://docs.ankiweb.net/editing.html#cloze-deletion).

- [x] **R2-006 · P2 · R — Дать способ написать буквальный синтаксис cloze.** Пример `{{c1::answer}}` внутри code тоже превращается в пропуск. Основание: [E03], [E04], R-E. **Готово:** documented escape или правило code позволяет учить сам синтаксис; предпросмотр и сохранённая карточка показывают одинаковый буквальный текст.

- [x] **R2-007 · P2 · R — Определять пустую сторону по содержимому, а не только текстовому индексу.** HTML-вопрос из одной картинки без alt генерирует ноль карточек, тогда как Markdown-картинка проходит. Основание: [E02], R-B. **Готово:** для поддерживаемых форматов видимый медиа-вопрос не исчезает; неподдерживаемый HTML получает явную конверсию/ошибку. Пустой условный reverse по-прежнему не создаётся.

- [x] **R2-008 · P1 · K — Устранить неработающее обещание CSS типов.** Редактор сохраняет `styling`, но `RichCard` принимает только kind/templates и не применяет его. Основание: [E05], [E06], [E07]. **Готово:** либо безопасный ограниченный стиль реально одинаково работает в preview/review, либо неработающий контрол убран с ясным объяснением; произвольный CSS в приложение не внедряется.

- [x] **R2-009 · P1 · K — Явно выбирать поле ответа Type-in.** Сейчас ответом считается последнее поле; добавление Extra способно незаметно сменить проверяемый ответ. Основание: [E16]. **Готово:** у типа есть однозначное поле проверки или фиксированный контракт; добавление/перестановка вспомогательных полей не меняет ответ, старые карточки совместимы.

- [x] **R2-010 · P1 · K — Сравнивать Type-in с текстом ответа, а не оформлением.** В target попадает raw field: `**Paris**`, ссылки и пояснения становятся частью ожидаемого ввода. Основание: [E16], [E32]. **Готово:** определена форма короткого ответа, Markdown не штрафует пользователя; варианты ответа задаются явно, без автоматического признания приблизительного ответа правильным.

- [x] **R2-011 · P2 · P — Диагностировать неотображаемый rich content до занятия.** Сейчас ошибки Mermaid сводятся к общему сообщению; автору нужен контекст конкретного поля/блока. Основание: [E04], [E05], [E10]. **Готово:** редактор показывает понятную ошибку формулы/диаграммы и безопасный исходник; в review ошибка оформления не скрывает остальные сведения и не блокирует выход/редактирование.

- [x] **R2-012 · P2 · K — Согласовать диаграммы с фактической темой.** Mermaid всегда инициализируется с `theme: 'dark'`. Основание: [E05]. **Готово:** светлые и тёмные семейства имеют читаемые диаграммы, смена темы перерисовывает их без устаревших SVG; сохраняется безопасный SVG sink.

## B. Жизненный цикл типов заметок и шаблонов

- [x] **R2-013 · P0 · K — Переименовывать поле вместе с существующими данными.** PATCH меняет определение поля, но не ключи `notes.fieldValues`; новый редактор может скрыть старое значение. Основание: [E06], [E07], [E08]. **Готово:** операция явно отображает старое поле в новое, обновляет ссылки шаблонов и значения атомарно; коллизия имён отклоняется, содержимое и расписание сохранены.

- [x] **R2-014 · P1 · K — Согласовывать состав карточек после изменения шаблонов.** PATCH типа только обновляет существующие совпавшие ord; новые карточки не появляются, исчезнувшие шаблоны оставляют старые. Основание: [E06]. **Готово:** до применения виден план create/keep/remove; после применения нет карточек без шаблона и недостающих обязательных карточек, история сохраняется для оставшихся.

- [x] **R2-015 · P0 · K — Не привязывать историю к меняющейся позиции шаблона.** `reindex()` сдвигает ord после удаления/перестановки, а существующее расписание сопоставляется именно по ord. Основание: [E02], [E06], [E07], [E09]. **Готово:** есть стабильная идентичность или явное отображение старых шаблонов в новые; перестановка A/B никогда не передаёт ответы A карточке B.

- [x] **R2-016 · P1 · K — Валидировать имена полей как идентификаторы схемы.** Сервер проверяет плотность ord, но не уникальность названий и неоднозначность пробелов. Основание: [E06]. **Готово:** дубли/пустые после trim имена отклоняются одинаково в UI/API; каждое поле сохраняет отдельное значение и однозначно адресуется шаблоном.

- [x] **R2-017 · P1 · P — Проверять шаблон до изменения всех заметок.** Нужна проверка неизвестных полей, незакрытых условий и пустого обязательного вопроса, а не только свободный ввод template string. Основание: [E02], [E06], [E07]. **Готово:** проблемное место видно автору; проверка включает несколько существующих заметок и объясняет допустимые пустые optional-reverse карточки.

- [x] **R2-018 · P1 · K — Сделать изменение kind отдельной осмысленной операцией.** API разрешает менять basic/cloze/typein/custom у используемого типа. Основание: [E06], [E08]. **Готово:** предварительная проверка данных и семантики генерируемых вопросов определяет допустимый переход; несовместимый переход не применяется тихо, FSRS не переезжает к другому вопросу.

- [x] **R2-019 · P2 · P — Завершить путь «изменил встроенный тип → применил к своим заметкам».** Clone-on-edit создаёт новый тип, прежние заметки остаются на встроенном. Основание: [E06], [E07], [E18]. **Готово:** интерфейс объясняет область изменений и предлагает явное преобразование выбранных заметок с отображением полей; встроенный тип для остальных пользователей неизменен.

- [x] **R2-020 · P1 · K — Обновлять уже открытые карточки после изменения/удаления типа.** Store обновляет список типов, но enriched карточки могут держать старый embedded noteType; удаление типа не вычищает его карточки из зеркала. Основание: [E18], [E16]. **Готово:** browser, preview и новая queue используют одну версию; удалённые карточки исчезают без полного reload, раскрытый вопрос не подменяется незаметно.

- [x] **R2-021 · P1 · K — Переиндексировать смысловой поиск после изменения типа.** Render-поля обновляются, но в модуле note-types отсутствует post-commit enqueueIndex. Основание: [E06], [E08]. **Готово:** изменённый шаблон обновляет производный индекс; no-op/style-only изменения не вызывают платные embeddings без изменения поискового текста, удалённые карточки не остаются в выдаче.

- [x] **R2-022 · P2 · V — Ограничить стоимость изменения популярного типа.** Сейчас все заметки обходятся по одной, карточки читаются и записываются внутри одной транзакции. Основание: [E06]. **Готово:** измерен сценарий 10 000 заметок, установлен бюджет времени/блокировок; пакетные запросы или ограничение операции удерживают его без частично применённого типа. Фоновый worker вводить только при доказанной необходимости.

- [x] **R2-023 · P1 · P — Показывать реальный объём удаления типа и путь сохранения заметок.** Удаление типа каскадно уничтожает заметки, карточки и историю. Основание: [E06], [E09], [E07]. **Готово:** серверный preview считает затронутые сущности во всей коллекции; пользователь может сначала преобразовать/экспортировать заметки, подтверждение не опирается на первые 500 карточек.

- [x] **R2-024 · P1 · V — Разрешать конфликт параллельных изменений одного типа.** PATCH читает target до транзакции и записывает объединённую форму без ожидаемой версии. Основание: [E06]. **Готово:** две вкладки с разными исходными версиями не затирают поля/шаблоны друг друга; конфликт сохраняет локальный draft и показывает актуальное определение.

## C. Создание и редактирование учебного материала

- [x] **R2-025 · P1 · P — Восстанавливать незавершённый draft.** Поля редактора живут в React state; закрытие вкладки теряет работу. Основание: [E10]. **Готово:** небольшой локальный draft привязан к пользователю и заметке/созданию, переживает reload, удаляется после подтверждённого save; при смене карточки предлагается сохранить/отбросить, чужому аккаунту draft недоступен.

- [x] **R2-026 · P1 · K — Защищать текст заметки от lost update.** PATCH передаёт полную карту полей без версии исходной заметки. Основание: [E08], [E10]. **Готово:** одновременные изменения в двух редакторах дают конфликт вместо тихой перезаписи; локальный текст можно сравнить, скопировать или применить поверх свежей версии осознанно.

- [ ] **R2-027 · P2 · P — Дать ограниченное восстановление предыдущего текста.** Ошибочное сохранение сейчас не имеет истории версий заметки. Основание: [E08], [E09]. **Готово:** несколько последних редакций с датой позволяют восстановить поля/теги без отката FSRS; есть ограничение объёма хранения, удаления аккаунта и экспорта. Без полноценного event sourcing.

- [x] **R2-028 · P1 · K — Предупреждать об уничтожении карточек при обычном редактировании.** Изменённое условное поле может убрать template ord; `applyNoteUpdate` сразу удаляет карточку с каскадом истории. Основание: [E08], [E09], [E10]. **Готово:** до save показываются удаляемые карточки и наличие повторений; подтверждённый план перепроверяется перед записью. Само изменение текста без смены состава не требует лишнего диалога.

- [x] **R2-029 · P2 · K — Предпросматривать все порождённые вопросы.** Редактор показывает template 0, даже когда заметка создаёт несколько карточек. Основание: [E10], [E02]. **Готово:** автор перебирает фактически генерируемые карточки и обе стороны; видит число будущих карточек, пустые optional templates объяснены. После R2-004 сюда входят отдельные cloze-номера.

- [x] **R2-030 · P1 · K — Валидировать пригодность вопроса по шаблону, а не первому полю.** UI требует непустое поле с ord 0, хотя вопрос может использовать другое. Cloze-проверка также отличается от API. Основание: [E10], [E08], [E02]. **Готово:** общая проверка допускает осмысленный custom вопрос с пустым служебным первым полем и одинаково отклоняет непригодные данные в ручном/API/AI пути.

- [x] **R2-031 · P2 · P — Безопасно преобразовывать заметку в другой тип.** Нужен явный field mapping и решение о соответствии карточек, а не смена select с потерей полей. Основание: [E10], [E08], [E09]. **Готово:** preview показывает сохранённые/отброшенные поля и судьбу расписаний; совместимые карточки сохраняют историю, остальные требуют осознанного решения.

- [ ] **R2-032 · P2 · P — Находить смысловые дубли при добавлении без обязательного AI.** Двойной клик уже защищён, но повторное ручное создание того же вопроса — другой сценарий. Основание: [E08], [E10]. **Готово:** точное нормализованное совпадение поля-вопроса в выбранной области даёт ссылку на существующую заметку; пользователь может продолжить намеренно, совместимые разные направления не блокируются.

- [ ] **R2-033 · P2 · P — Добавлять серию заметок с предсказуемыми настройками.** Нужен непрерывный путь для набора десятков карточек. Основание: [E10]. **Готово:** «сохранить и добавить следующую» очищает только учебные поля, сохраняет явно выбранные deck/type и при желании теги, сообщает число созданных карточек и возвращает фокус; ошибка не очищает введённое.

- [ ] **R2-034 · P2 · P — Создавать вариант заметки без копирования её расписания.** Полезно для близких примеров и языковых конструкций. Основание: [E08], [E10], [E09]. **Готово:** «создать копию» открывает новый draft с полями/тегами/ссылками на доступные медиа; новые UUID и FSRS создаются только при save, original и его история неизменны.

- [ ] **R2-035 · P2 · P — Создавать cloze из выделения с контролем номера.** Ручной ввод вложенных скобок делает ошибки особенно вероятными после добавления настоящих c1/c2. Основание: [E10], [E03]. **Готово:** выделение оборачивается в новый или выбранный номер, preview показывает получившиеся вопросы; операция отменяется обычным undo текста и не меняет код/формулы вне выделения.

- [ ] **R2-036 · P2 · K — Нормализовать теги одинаково во всех путях записи.** Ручной ввод разделяет строку запятыми без единой дедупликации; bulk использует другие правила. Основание: [E10], [E08], [E12]. **Готово:** определены пробелы, регистр, Unicode, ограничения длины/числа и дубли; UI/API/импорт дают одинаковые теги, существующие отличающиеся по регистру теги не сливаются без preview.

## D. Расписание, учебный день и нагрузка

- [ ] **R2-037 · P2 · P — Поддержать учебный день пользователя.** Сейчас бюджет и rollup живут по UTC, что уже принято первым проходом. Основание: [E11], [E25], [E29]. **Готово:** один timezone/day-boundary применяется к лимитам, streak, занятиям и статистике; перевод часов и смена зоны не дают двойной бюджет и не отнимают вчерашние результаты. Это изменение контракта, не скрытая замена UTC в одном компоненте.

- [x] **R2-038 · P1 · P — Определить совместную работу лимитов коллекции, родителя и дочерней колоды.** Общая очередь берёт global defaults, а счётчики расхода общие даже для разных presets. Основание: [E12], [E13], [E29]. **Готово:** примеры «колоды A/B по 10 новых», «родитель 15», «учить всё» имеют одну объяснимую политику и одинаковые серверные/UI числа; новый policy явно заменяет текущий.

- [x] **R2-039 · P1 · V — Проверить превышение дневного бюджета параллельными очередями.** Grade защищает версии карточек, но две вкладки могут заранее получить разные последние доступные новые карточки. Основание: [E11], [E12]. **Готово:** воспроизведён сценарий с остатком 1; выбран и реализован мягкий либо строгий лимит, превышение не возникает неожиданно. Не вводить резервирование карточек, если достаточно проверки при grade.

- [ ] **R2-040 · P2 · P — Разводить связанные вопросы одной заметки по дням.** Несколько templates одной заметки могут сразу подсказывать друг другу ответ. Основание: [E02], [E09], [E12]. **Готово:** опциональное bury siblings учитывает noteId во всех колодах, не сбрасывает FSRS, не прячет обязательный learning без отдельного решения; отмена оценки восстанавливает соответствующее действие. Ориентир: [siblings и bury](https://docs.ankiweb.net/studying.html#siblings-and-burying).

- [ ] **R2-041 · P2 · P — Отложить карточку до следующего учебного дня.** Skip меняет место в текущей очереди, suspend действует бессрочно. Основание: [E15], [E09]. **Готово:** пользователь может временно убрать карточку/заметку и вернуть её досрочно; состояние объяснено в счётчиках, переживает reload и не записывает оценку. Использовать общую основу с R2-040.

- [ ] **R2-042 · P2 · P — Управлять смешиванием новых и повторяемых карточек.** Текущий фиксированный порядок может откладывать новые до конца большого backlog. Основание: [E12], [E15]. **Готово:** небольшой набор понятных режимов, например «сначала повторы» и «чередовать»; срочный learning сохраняет приоритет, фильтры/лимиты не обходятся, порядок устойчив внутри занятия.

- [x] **R2-043 · P1 · K — Завершить жизненный цикл проблемной карточки (leech).** Auto-suspend срабатывает только при первом переходе через threshold; после ручного возврата повторные провалы больше не пересекают его. Основание: [E11], [E14], [E22]. **Готово:** понятны причина остановки, исправление, возврат и повторное обнаружение; изменение threshold не создаёт необъяснимых исключений. Не наказывать пользователя новыми автоматическими сбросами истории.

- [x] **R2-044 · P1 · K — Сделать Set Due осмысленным для каждого FSRS state.** Сейчас меняется только due; новая карточка остаётся new и выбирается независимо от этой даты. Основание: [E12], [E14]. **Готово:** preview объясняет переход new/learning/review и результат даты; одиночное и массовое действие одинаковы, setDue не обещает отсрочку, которую queue игнорирует.

- [ ] **R2-045 · P2 · P — Разделить возврат в новые и полное обнуление счётчиков.** Forget обнуляет reps/lapses, сохраняет review history и не снимает suspended. Основание: [E12], [E14]. **Готово:** одно понятное окно объясняет что меняется, предлагает минимально необходимые варианты; после действия состояние в очереди, карточке и истории согласовано, сохранённая история не выдаётся за новую.

- [ ] **R2-046 · P2 · P — Показывать влияние изменения preset на реальную коллекцию.** Нужны затронутые прямые/наследующие колоды и явная политика существующих due. Основание: [E13], [E30], [E31]. **Готово:** перед save видны область действия и применение только к будущим оценкам либо отдельная осознанная пересортировка расписания; изменение retention не обещает мгновенный пересчёт уже назначенных дат.

- [ ] **R2-047 · P1 · V — Согласовать показанный интервал с актуальными настройками оценки.** Web считает preview по зеркалу presets/profile, сервер — по свежим данным, fuzz также независим. Основание: [E16], [E11], [E14]. **Готово:** изменение preset в другой вкладке не даёт необъяснимого скачка; UI либо обновляет preview перед ответом, либо честно показывает приблизительный интервал. Сравнить реальные записанные due на фиксированных примерах.

- [ ] **R2-048 · P2 · K — Ограничить и сделать точным кэш FSRS-настроек.** Ключ округляет retention до 3 знаков, параметры конструктора не округляются; Map не ограничен. Совпадение scheduler для 0.9011 и 0.9014 воспроизведено. Основание: [E14], R-F. **Готово:** одинаковый ключ всегда означает одинаковые параметры; перебор presets не растит память бесконечно, расчёты на текущих настройках сохраняются.

## E. Непрерывное занятие и восстановление

- [x] **R2-049 · P1 · P — Восстанавливать саму сессию после reload/закрытия браузера.** Первый проход восстановил серверную очередь, но ledger ответов и активный вопрос живут в памяти. Основание: [E15], [E16], [E17]. **Готово:** небольшой checkpoint возвращает контекст, подтверждённые ответы и счётчики после сверки версий с сервером; не реплеит оценки и не хранит бесконечно полную коллекцию.

- [x] **R2-050 · P1 · K — Разрешать неопределённый результат grade после потери ответа сети.** Версионный конфликт предотвращает второй grade, но не сообщает клиенту результат первого. Основание: [E11], [E16]. **Готово:** повтор с одним operationId возвращает тот же review либо endpoint позволяет проверить его; FSRS/XP меняются один раз, ledger и undo получают реально сохранённую оценку. Это расширение прежней защиты от двойного клика.

- [x] **R2-051 · P1 · P — Возвращать человека в занятие после истечения авторизации.** Нужен отдельный путь 401 во время чтения, раскрытия и сохранения. Основание: [E16], [E18]. **Готово:** карточка и typed draft сохраняются в пределах того же пользователя, после входа версия сверяется; приложение не отправляет прежний ответ автоматически от другого аккаунта.

- [x] **R2-052 · P2 · P — Согласовывать занятие с действиями другой вкладки/устройства.** Текущая защита срабатывает преимущественно при попытке записать устаревшую карточку. Основание: [E11], [E16], [E19]. **Готово:** возврат фокуса обнаруживает новую версию/удаление до оценки и сохраняет введённое; для вкладок достаточно лёгкого сигнала об изменении, для устройств — refetch. WebSocket не обязателен.

- [ ] **R2-053 · P2 · V — Удержать память в длинной сессии.** History хранит полные before/after карточки и review на каждый ответ; undo-depth не ограничен. Основание: [E15]. **Готово:** измерена сессия с тысячами ответов и тяжёлыми полями; totals отделены от ограниченного окна undo, история/итоги не теряются при ограничении памяти. Обычная короткая сессия не усложняется.

- [ ] **R2-054 · P2 · P — Задавать размер одного занятия без изменения дневного бюджета.** Дневные ограничения и кнопка завершения уже есть; недостаёт намерения «10 карточек / примерно 5 минут». Основание: [E12], [E15], [E16]. **Готово:** выбранный session target завершает занятие предсказуемо, явно различает уникальные карточки и ответы, объясняет оставшийся learning; серверное расписание не обрезается.

- [ ] **R2-055 · P2 · P — Явно ставить занятие на паузу.** Таймер исключает скрытую вкладку, но открытая карточка на оставленном ноутбуке считается активностью. Основание: [E15], [E16]. **Готово:** pause/resume исключает паузу из времени и сохраняет вопрос/typed answer; опциональный idle timeout не ставит оценку, не теряет ввод и сообщает о себе.

- [x] **R2-056 · P1 · R — Показывать последний результат, а не старый объект в памяти вкладки.** `readStudyResult` предпочитает inMemory более свежему localStorage другой вкладки. Основание: [E17], R-G. **Готово:** сравнение завершения/идентичности результата выбирает актуальный отчёт, storage event обновляет открытую страницу; результаты разных пользователей строго разделены.

- [x] **R2-057 · P3 · P — Сохранять небольшую историю законченных занятий.** Сейчас доступен только последний локальный summary без серверного sessionId. Основание: [E17], [E09]. **Готово:** список занятий с устойчивой идентичностью и ссылкой на реальные reviews доступен на втором устройстве; undo корректирует затронутый итог. Реализовывать после R2-050, без дублирования полного содержимого карточек.

- [ ] **R2-058 · P1 · V — Проверить длинные learning/relearning ступени и переходы суток.** Настройки допускают дни, а локальное удержание ограничено 20 минутами. Основание: [E14], [E15], [E16]. **Готово:** сценарии 19/20/21 минут, 1 день, смена preset посреди learning и возвращение через несколько дней дают правильный следующий шаг; нет зависшего ожидания, досрочного показа или потери карточки.

- [x] **R2-059 · P1 · V — Переживать сон устройства и скачки системных часов.** Due сравнивается с Date.now плюс offset, длительность — с performance.now. Основание: [E15], [E16]. **Готово:** сон на час, ручной сдвиг часов и медленный ответ queue не показывают неверное ожидание и не отправляют завышенную длительность; после пробуждения выполняется одна актуальная сверка.

- [ ] **R2-060 · P2 · P — Предложить простой режим двух оценок.** Четыре оценки уже объяснены; новичку может хватить «не вспомнил / вспомнил». Основание: [E16], [E14]. **Готово:** режим явно отображается в Again/Good, имеет корректные интервалы и клавиши, не меняет старые review rows; расширенный режим остаётся доступен. Допустимость подхода: [кнопки ответов Anki](https://docs.ankiweb.net/studying.html#answer-buttons).

## F. Дополнительное обучение и уход за карточками

- [ ] **R2-061 · P2 · P — Отделить тренировку без изменения расписания от filtered review.** Сейчас filtered/cram действительно меняет FSRS, что уже честно обозначено первым проходом. Основание: [E11], [E20], [E21]. **Готово:** отдельный явно выбранный preview/practice не меняет due/reps/lapses/обычные метрики; режим с пересчётом остаётся прежним. Протокол не маскирует тренировку под обычный grade.

- [ ] **R2-062 · P2 · P — Предпросматривать фактическую выборку saved filter.** Валидная строка не объясняет, сколько карточек найдётся и какие будут пропущены. Основание: [E20], [E21], [E12]. **Готово:** до старта видны total/выбранные по limit/примеры, будущие due и исключённые suspended; расчёт использует серверный query engine, а не bootstrap mirror.

- [ ] **R2-063 · P2 · P — Фиксировать состав и случайный порядок filtered-занятия.** Random пересчитывается при каждом запросе; mutable query может вернуть другую выборку после восстановления. Основание: [E12], [E20], [E15]. **Готово:** начатый session сохраняет seed/список выбранных id или эквивалентный bounded snapshot; «пересобрать» — отдельное действие, удалённые/недоступные карточки безопасно выпадают.

- [ ] **R2-064 · P2 · P — Собирать обычный фильтр без изучения query language.** В форме сейчас в основном строка query и sort. Основание: [E21], [E23]. **Готово:** deck/tag/state/overdue задаются понятными контролами, преобразуются в существующий AST/синтаксис, advanced режим сохраняет ручной запрос без неожиданного переписывания.

- [ ] **R2-065 · P2 · V — Сохранить смысл saved filter после переименования структуры.** Фильтр хранится строкой и может ссылаться на имена колод, полей и тегов. Основание: [E20], [E23], [E30]. **Готово:** проверены rename/move/delete deck и rename tag/type; сломанная ссылка явно диагностируется либо сохраняется стабильная идентичность, пустая выборка не выдаётся за отсутствие материала.

- [ ] **R2-066 · P2 · P — Запускать разовую тренировку без мусора в сохранённых фильтрах.** Сохранённая filtered deck — текущая единица запуска. Основание: [E20], [E21]. **Готово:** быстрый запуск из параметров не создаёт постоянную сущность без запроса пользователя; «сохранить этот фильтр» остаётся явным действием, повторный вход не размножает записи.

- [ ] **R2-067 · P2 · P — Переносить выбранную область в custom study.** Начало из колоды/поиска должно сохранять намерение пользователя. Основание: [E21], [E22], [E30]. **Готово:** переход с deck subtree или выбранного search query открывает соответствующий preview; область заметно отображается до старта, сохранение фильтра не расширяет её на всю коллекцию.

- [ ] **R2-068 · P2 · P — Объяснять ошибки и неоднозначность запросов в месте ввода.** Неизвестный ключ сейчас может трактоваться как обычный текст; синтаксическая валидность не гарантирует намерение. Основание: [E23], [E21], [E22]. **Готово:** опечатка в операторе получает ненавязчивую диагностику/подсказку; сложный валидный запрос не переписывается автоматически, RU/EN объясняют точную позицию ошибки.

- [ ] **R2-069 · P2 · P — Дать явное одноразовое увеличение сегодняшнего лимита.** Сейчас пользователь может уходить в filtered mode, где другие правила расхода бюджета. Основание: [E12], [E13], [E21]. **Готово:** «ещё N новых/повторов сегодня» имеет отдельное ограниченное действие и прозрачный остаток; не меняет постоянный preset и не превращает будущие карточки в due.

- [ ] **R2-070 · P2 · P — Приостанавливать и возвращать карточку прямо из занятия.** Редактирование и переход в browser есть, но действие ухода за проблемным вопросом должно укладываться в текущий контекст. Основание: [E16], [E12]. **Готово:** suspend card/note явно различаются, очередь обновляется только после успеха, доступна отмена; никакой автоматической оценки или потери typed draft при ошибке.

- [ ] **R2-071 · P2 · P — Открывать полную историю конкретной карточки.** Данные cardProgress существуют на сервере, но пользователю нужен компактный inspect-путь. Основание: [E25], [E16], [E22]. **Готово:** видны прежние оценки, интервалы, сбросы/ручные изменения при наличии данных и эффективные настройки; открытие не раскрывает ответ заранее и возвращает к той же позиции.

- [ ] **R2-072 · P2 · P — Отмечать материал для доработки, не ломая расписание.** Suspend не должен быть единственным способом запомнить плохой вопрос. Основание: [E09], [E16], [E22]. **Готово:** «исправить позже» доступно из review, находит карточки отдельным фильтром и снимается после правки; первая версия может использовать обычный note tag с ясной областью действия.

## G. Коллекция, поиск и массовые операции

- [ ] **R2-073 · P2 · P — Давать полный размер результата и объяснимую навигацию по нему.** Cursor/load-more уже исправлены; остаётся планирование работы с большой выдачей. Основание: [E12], [E22]. **Готово:** пользователь различает «загружено» и «найдено», возврат из редактора сохраняет query/sort/позицию; count вычисляется сервером с тем же фильтром и разумной стоимостью.

## H. Статистика, которой можно доверять

- [ ] **R2-085 · P1 · K — Считать Hard успешным воспоминанием либо переименовать метрику.** Сейчас retention в SQL и UI — `rating >= 3`, что считает Hard неуспехом при объяснении «вспомнил с трудом». Основание: [E24], [E25], [E16]. **Готово:** единая формула/терминология используется в stats, home, итогах и AI read-tools; набор Again/Hard/Good/Easy даёт 75% recall success, либо отдельно показывается другая явно названная метрика. Ориентир: [значения оценок](https://docs.ankiweb.net/studying.html#answer-buttons).

- [ ] **R2-086 · P1 · K — Разделить долю успешных ответов и true retention.** Все попытки learning/relearning сейчас участвуют в общей доле; interval curve использует каждый соседний review через LAG. Основание: [E25], [E24]. **Готово:** метрики названы по точному знаменателю; при выборе true retention учитывается первая подходящая проверка карточки за день, повторные попытки не улучшают его искусственно. Ориентир: [true retention Anki](https://docs.ankiweb.net/stats.html#true-retention-table).

- [ ] **R2-087 · P1 · K — Сохранять происхождение review и фильтровать статистику по режиму.** `source: filtered` используется при grade, но не записывается в reviews. Основание: [E11], [E09], [E25]. **Готово:** новые строки различают regular/filtered и будущий practice, аналитика объясняет включённые режимы; старые строки отмечены unknown, а не произвольно переклассифицированы.

- [ ] **R2-088 · P1 · K — Считать статистику колод по всей базе, включая потомков.** Home/decks уже исправлены; `NNStats.perDeck` всё ещё считает cards из ограниченного зеркала и только прямой deckId. Основание: [E24], [E18], [E29]. **Готово:** серверный breakdown совпадает с полной коллекцией >500 карточек, явно различает own/subtree и не складывает повторно дочерние totals.

- [ ] **R2-089 · P1 · K — Показывать настоящие FSRS-показатели вместо выдуманного ease.** `ease = (10 - difficulty) / 2.5`, а mature — любой State.Review. Основание: [E24]. **Готово:** отображаются difficulty/stability/interval с корректными единицами; mature имеет явно определённый порог, new не искажает среднюю difficulty. Для совместимого обозначения mature ориентир — [статистика Anki](https://docs.ankiweb.net/stats.html).

- [ ] **R2-090 · P1 · K — Показывать актуальную цель удержания.** График и target line жёстко нарисованы на 90%, хотя профиль/preset настраиваемы. Основание: [E24], [E13], [E31]. **Готово:** deck scope показывает effective retention; смешанная коллекция не выдаёт один случайный target за общий, подпись/линия/расчёт используют одну величину.

- [ ] **R2-091 · P1 · K — Убрать ложные значения из графиков.** Дни без ответов рисуются как 0% retention; sparkline среднего grade использует другую формулу, а XP — количество reviews. Основание: [E24]. **Готово:** отсутствие данных даёт разрыв/нейтральное состояние; каждый график строится из той же метрики, что его число, или убран до появления соответствующей истории.

- [ ] **R2-092 · P1 · K — Согласовать календарную агрегацию уже при текущем UTC-контракте.** SQL date_trunc зависит от timezone подключения, UI делит локальные сутки на 86 400 000 мс. Основание: [E25], [E24]. **Готово:** разные PostgreSQL TimeZone и дни DST дают те же ожидаемые bucket counts; UTC задаётся явно, будущий R2-037 меняет политику централизованно.

- [ ] **R2-093 · P1 · K — Загружать аналитические агрегаты без полного неограниченного журнала.** `/reviews` делает select всех полей, включая undoSnapshot; UI отдельно забирает 30 и 7 дней и фактически выполняет await последовательно. Основание: [E11], [E24]. **Готово:** обзор получает bounded aggregates параллельно, детальная история пагинируется и не несёт лишний snapshot; аккаунт с годами повторений не замораживает экран.

- [ ] **R2-094 · P2 · P — Объяснить, что именно прогнозируется.** Due forecast считает текущие назначенные даты, а не все будущие повторы и ещё не изученные карточки. Основание: [E25], [E24], [E29]. **Готово:** backlog, уже назначенные даты и предположительная новая нагрузка явно разделены; первая версия может честно подписывать только достоверный прогноз, без псевдоточной симуляции FSRS.

- [ ] **R2-095 · P2 · K — Не выдавать самый активный час за доказанное лучшее время учёбы.** Peak выбирается по количеству ответов, подпись покрывает два часа, retention берётся за один; размер выборки не виден. Основание: [E24]. **Готово:** окно и формула совпадают, есть n и нейтральное состояние малого объёма; текст не делает причинного вывода о качестве обучения из частоты занятий.

- [ ] **R2-096 · P2 · P — Переходить от метрики к конкретному материалу.** Пользователю нужно действие после просмотра трудных/просроченных карточек. Основание: [E24], [E25], [E22]. **Готово:** нажатие открывает тот же deck/time/state scope в истории или browser; агрегат и детализация имеют одинаковые определения и user scope, нулевой результат объяснён.

## Воспроизведённые примеры до исправлений

Это снимок первоначального аудита: после закрытия соответствующих пунктов команда ниже должна показывать исправленное поведение. Тогда были вызваны существующие функции через Bun 1.3.14, без записи в БД, S3 или браузерный профиль. Для renderer использован существующий test DOM harness; это функциональное воспроизведение, не проверка настоящего screen reader или мобильного Safari.

| Проба | Функция/вход | Фактический результат |
| --- | --- | --- |
| R-A | sanitizeFieldHtml: fenced TypeScript `const value: Array<T> = [];` | Сохранится `const value: Array = [];` |
| R-A | sanitizeFieldHtml: inline HTML-пример кнопки | Останется только текст `OK` внутри backticks |
| R-A | sanitizeFieldHtml: script в fenced HTML-примере | Содержимое блока удалено; опасный script при этом не исполнялся |
| R-B | generateCards(BASIC): Front = inline code `Array<T>` | renderFrontText = `Array` |
| R-B | generateCards(BASIC): Front = один raw HTML img без alt | `[]`, карточка не генерируется |
| R-B | generateCards(BASIC): Front = Markdown image с пустым alt | Карточка есть; renderFrontText содержит исходный media token |
| R-C | generateCards(CLOZE): c1 Paris, c2 France | 1 карточка, front `[…] is in […]` |
| R-C | stripCloze: `{{c1::Paris::city}}` | prompt `[…]`, answer `Paris::city` |
| R-C | stripCloze: `{{c1::x^{2}}}` | prompt `[…]}`, лишняя закрывающая скобка |
| R-C | stripCloze: вложенный c2 внутри c1 | Повреждённая строка с оставшейся cloze-разметкой |
| R-D | renderCardHtml: inline и fenced code с `\(x\)` | Найден `.katex`, видимый текст `x`, буквальные delimiters потеряны |
| R-E | renderCardHtml(CLOZE): inline code с `{{c1::answer}}` | prompt `[…]`, back `answer`, буквальный синтаксис потерян |
| R-F | getScheduler(0.9011) === getScheduler(0.9014) | `true`, общий cache key |
| R-G | saveStudyResult(completedAt=100), затем storage=200 | readStudyResult возвращает completedAt=100 |

## Как выполнять следующий проход

Для K/V сначала добавить минимальное воспроизведение конкретного риска. Для P сначала зафиксировать пользовательский контракт и простейшую достаточную реализацию. Закрывать пункт только после выполнения его критерия, проверки зависимостей и записи результата рядом с ним. Зеленая прежняя suite сама по себе не закрывает новые сценарии.

В рамках этого аудита выполнены чтение реализации, приведённые функциональные пробы и проверка самого backlog. Полный test/build повторно не запускался: продуктовый код не менялся. P0/P1 не считаются исправленными от того, что они внесены в список; прежний отчёт приёмки остаётся свидетельством только своего набора сценариев.

Проверка документа: 120 уникальных последовательных ID, у каждого есть основание и критерий готовности; 34 ссылки ведут в существующие исходники/отчёты, номера строк проверены; опубликованная команда воспроизведения выполнена успешно. Отдельно сопоставлены старые 81 пункта: защищённый клик отличается от retry после lost response, восстановление queue — от восстановления session ledger, home/deck counts — от статистики, мобильный viewport — от физического Safari и screen reader. Повторный полный test/build не объявляется частью уже выполненной работы этого аудита.
