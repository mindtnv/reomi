# Design

## Context

See proposal.md. The existing documentation queue and run UUID fence page commits. Manual update discovers outside a transaction, then locks the owner library and connection before queuing. These boundaries can serve scheduled updates too.

## Decisions

- Add schedule (`off|daily|weekly`), nextSyncAt, claimId/claimUntil, failure count, last schedule error and last completed summary to connections. Add per-page lastChange (`added|updated|unchanged|null`). Defaults keep old callers and connections manual. No change to source/card ownership.
- A single process pump handles one due discovery only when no page import is queued. A conditional database claim sets a new UUID and a five-minute expiry; expired claims are reclaimable. The due index supports enabled/inactive selection. No long database transaction wraps network work.
- Scheduled update passes the claim UUID through discovery and revalidates it under the connection lock. Settings changes clear the claim and replace the due date; manual update rejects a live discovery claim. Stale discovery cannot queue pages or overwrite errors. Cancelled imports do not restart automatically; explicit resume remains required.
- Successful queuing releases the claim and advances the next check by the chosen period. Discovery failures increment capped retries (15 minutes, 30 minutes, 1 hour up to 6 hours), retaining saved material. Missing folders or quota failures show their existing actionable codes. Page failures remain visible and retry on the normal next schedule.
- Save lastChange inside the page/source commit; reset it when queuing a new run. Finish aggregates committed outcomes into a persistent summary. Interrupted runs retain committed outcomes until recovery completes. Cancelled runs do not replace the last completed summary.
- Use the existing collection controls and shared select; show schedule, next check, last result and compact change counts. Poll active discovery as well as page import; account-keyed state rejects outgoing account responses. No push/email notification.

## Migration and rollback

Additive migration after 0050, generated by Drizzle. Deploy schema/API before web. Older API ignores new columns and does not run schedules; keep columns and summaries on rollback. No data backfill besides safe defaults. Update migration-head contract pins without removing previous-chain assertions.

## Risks

- [Discovery stalls] → existing guarded fetch deadlines plus claim expiry/fencing.
- [Schedules fill capacity] → same reservations/quota transaction, visible failure and retry; no partial manifest import.
- [Replica/restart races] → atomic claim UUID and commit predicates; reuse existing page-run fencing. The existing single API deployment remains the production topology.
