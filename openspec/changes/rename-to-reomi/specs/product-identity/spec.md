## Purpose

Зафиксировать пользовательское имя Reomi и сохранить сессию, локальные предпочтения и серверные данные при переименовании NeuroNexus.

## ADDED Requirements

### Requirement: User-visible product name
Пользовательские поверхности SHALL называть продукт Reomi. Сюда входят тема и обращение письма сброса пароля, текст инструкций MCP, realm в `WWW-Authenticate`, User-Agent чтения внешних страниц и имена файлов, которые браузер скачивает по действию пользователя. Заголовок приложения, манифест и уже поставленные строки интерфейса MUST оставаться Reomi. Внутренние имена классов, компонентов и внутрипроцессных событий MUST NOT становиться частью этого контракта.

#### Scenario: Password reset email
- **WHEN** пользователь запрашивает сброс пароля
- **THEN** тема и текст письма называют продукт Reomi
- **AND** ссылка по-прежнему ведёт на канонический веб-оригин приложения

#### Scenario: Downloaded personal file
- **WHEN** пользователь скачивает экспорт аккаунта или локальный черновик
- **THEN** предлагаемое имя файла использует имя Reomi
- **AND** содержимое остаётся данными только этого пользователя

### Requirement: Session survives the rename
Переименование MUST NOT менять секрет аутентификации, имя сессионной куки и привязку сессии к уже выданной записи. Пользователь с действующей сессией на каноническом API MUST оставаться аутентифицированным после выкладки переименования. Смена префикса куки или секрета в рамках этого change запрещена.

#### Scenario: Open session on the canonical API
- **WHEN** у пользователя есть действующая сессия на `https://api.reomi.ru` и выкладывается переименование
- **THEN** следующий запрос с той же кукой остаётся сессией того же пользователя
- **AND** данные другого пользователя не возвращаются

#### Scenario: No secret rotation
- **WHEN** сравнивают конфигурацию аутентификации до и после переименования
- **THEN** секрет и имя сессионной куки не изменены этим change

### Requirement: Browser preferences survive the key rename
Сохранённые в этом браузерном origin настройки с префиксом `nn:` SHALL читаться после перехода на префикс `reomi:`. Приложение MUST предпочитать уже записанное значение `reomi:` и MUST NOT удалять соответствующий ключ `nn:` в первом релизе миграции. Недоступное или повреждённое хранилище MUST NOT стирать уцелевшее значение и MUST оставлять приложение пригодным к работе. Предпочтения другого origin, включая бывший веб-хост, этот change не копирует.

#### Scenario: Existing theme and drafts
- **WHEN** в origin `https://app.reomi.ru` есть только прежние ключи темы, ширины панелей и черновиков
- **THEN** приложение восстанавливает эти значения под новыми ключами
- **AND** прежние ключи остаются в хранилище

#### Scenario: Preference written after migration
- **WHEN** новое значение уже записано в ключе `reomi:` и старый ключ `nn:` содержит более раннюю копию
- **THEN** приложение использует значение `reomi:`

#### Scenario: Storage unavailable
- **WHEN** хранилище браузера недоступно или прежнее значение повреждено
- **THEN** приложение не удаляет другой уцелевший ключ и остаётся пригодным к работе

#### Scenario: Appearance before first paint
- **WHEN** пользователь перезагружает приложение после появления только старого ключа темы
- **THEN** первая отрисовка использует ту же палитру и режим, что и до переименования ключа
- **AND** прежние строковые значения темы по-прежнему сохраняют свой внешний вид

### Requirement: Server-owned data is not relocated
Переименование MUST NOT переносить, переписывать или удалять учётные записи, карточки, источники, медиа и строки базы. Имя прод-базы, роль подключения и бакет медиа MUST оставаться прежними в этом change.

#### Scenario: Existing account after rename
- **WHEN** существующий пользователь входит на каноническом origin после переименования
- **THEN** он видит свои прежние данные
- **AND** границы доступа между пользователями не меняются
