# Design

## Context

См. предложение, раздел Why. Ниже только факты, от которых зависит устройство.

Сейчас веб уже ставится как приложение. `apps/web/src/app/manifest.ts` задаёт `display: "standalone"`, `display_override: ["window-controls-overlay"]` и значки 192, 512 и maskable. `apps/web/src/app/layout.metadata.ts` включает `appleWebApp.capable`. `apps/web/src/app/sw.ts` регистрирует Serwist с пустым precache. `apps/web/next.config.ts` выкидывает все записи манифеста кэша, не задаёт `runtimeCaching` и отключает worker в `next dev`. Кэша нет намеренно. Сервер остаётся источником данных.

`apps/web/src/lib/notify.ts` создаёт `Notification` один раз после загрузки, если в хранилище браузера включён флаг и разрешение уже выдано. Комментарий файла прямо исключает фоновую доставку. Те же слова стоят в `settings.notifications` для английского и русского. `apps/web/src/lib/app-badge.ts` вызывает `setAppBadge`, пока документ открыт. `Bootstrap` берёт число из `totalAvailable` обзора учёбы.

Почта уже умеет метку `notification` в `packages/auth/src/email.ts`. Провайдер выбирается по наличию `RESEND_API_KEY`. Снимок отмены оценки в `UndoSnapshot` перечисляет поля профиля явно. Отдельной таблицы напоминаний нет. Отдельного планировщика нет. Остановка API в `apps/api/src/index.ts` ждёт именованные drain. `GET /ready` показывает снимки `index`, `sourceIngest` и `artifact` без идентификаторов пользователей.

Учебный день, серия и бюджеты считаются по UTC. Смена этого договора не входит в работу. Открытый пункт про местный учебный день остаётся отдельным.

Внешние ограничения, сверенные по документам в этой сессии, а не измеренные на устройствах в РФ.

Web Push с VAPID не требует проекта Firebase и не требует `gcm_sender_id`. Chrome при этом всё равно выдаёт endpoint `https://fcm.googleapis.com/fcm/send/`. Так устроен Chromium, это не отдельный SDK в приложении. Firefox ходит в autopush Mozilla. Safari на macOS 13 и Home Screen web app на iOS 16.4 и новее ходят в APNs. Apple пишет, что для Web Push не нужен Apple Developer Program, невидимый push запрещён, лимит тела 4 КБ, а серверу нужен исходящий доступ к `https://*.push.apple.com`. Жест пользователя обязателен. Бейдж на iOS есть у Home Screen web app с 16.4 и не заменяет видимое уведомление. По MDN числовой Badging API нет в Chromium на Android. Непрочитанное уведомление само ставит знак на иконке. Настольный бейдж Chromium рассчитан на установленное приложение в Windows и macOS.

Пока процесс браузера жив, service worker на настольном Chrome может получить push и без открытого окна. Полностью завершённый браузер push не примет. На Android система может поднять браузер.

Push SDK RuStore 6.4.0 рассчитан на Android-приложение. Ему нужны загрузка в консоль, пройденная модерация, установленный RuStore, совпадение подписи и разрешение фоновой работы, иначе доставка запаздывает. Сайт этот SDK не вызывает. Официальный плагин push в Capacitor на Android требует Firebase и `google-services.json`.

Плагин уведомлений Tauri 2 показывает системный toast, пока процесс запущен. Плагин `tauri_plugin_push_notifications` на desktop отклоняет регистрацию. На Android он использует FCM, на iOS APNs. Electron показывает уведомление из живого процесса. Подпись нужна и Windows, и macOS.

Один отчёт на Habr от 1 мая 2026 описывает отказ модерации RuStore формулировкой «оболочка над сайтом» и более позднюю приёмку после расширения нативной части. Это один случай автора, не цитата правил RuStore.

Долю отказов FCM в российских сетях эта сессия не измеряла. Её должен показать журнал квитанций после запуска.

## Goals / Non-Goals

**Goals:**

- Одно напоминание о готовых карточках и одно предупреждение о серии доходят при закрытом окне туда, где канал реально существует.
- Почта закрывает iPhone без иконки на Home Screen, Chromium с недоступным FCM и полностью закрытый настольный браузер.
- Установка PWA объясняется там, где без неё iOS не даст push.
- Worker по-прежнему не кэширует.
- Настройки не откатываются вместе с оценкой.

**Non-Goals:**

- Оболочки Tauri, Electron и Capacitor, листинг RuStore и бот Telegram.
- Местный учебный день вместо UTC.
- Офлайн-чтение колод.
- Проект Firebase.
- Числовой бейдж на Android как обязательство.

## Decisions

### 1. Сначала серверное напоминание на текущем PWA

Человек с карточками к повторению получает один дайджест после выбранного местного часа и, отдельно, одно предупреждение, если серия ещё не подтверждена в этот учебный день UTC. Оба текста короткие. Оба ведут на `/review` канонического веба. Содержание карточек не уходит.

Оболочка не создаёт это напоминание. Ей всё равно нужен тот же сервер, те же настройки и та же квитанция. Поэтому первый поставляемый результат состоит из таблиц, тика и двух каналов. Иконка в доке и бинарник магазина остаются следующими развилками, и только по измеренной дыре.

Альтернатива «сразу Capacitor, потому что аудитория в РФ» отложена. iOS уже получает APNs через Home Screen web app без программы разработчика Apple. Запасной плагин Capacitor на Android возвращает к FCM. RuStore Push закрывает именно Android без опоры на Google, но это отдельное приложение, консоль и модерация. Его имеет смысл мерить по доле квитанций `fcm`, а не начинать до первой отправки.

Альтернатива «сразу Tauri или Electron» отложена. Оба показывают системное уведомление из живого процесса. Закрытое настольное приложение само не просыпается от Web Push, если только браузер или трей не оставлены в памяти. Телефон в кармане от этого не выигрывает. Electron ещё и тащит свой Chromium, а его push снова смотрит в FCM. Tauri легче по размеру установщика, но его push-плагин на desktop не регистрируется.

### 2. Сравнение оболочек

| Оболочка | Что видит человек | Доставка в РФ | Объём рядом с текущим Coolify | Главный риск |
| --- | --- | --- | --- | --- |
| PWA, этот change | Тот же сайт, подсказка установки, письмо и push установленного приложения | iOS через APNs после Home Screen. Firefox через Mozilla. Chromium через FCM. Письмо не зависит от этих сетей | Одна миграция, модуль API, правки worker и настроек, переменные VAPID, исходящий доступ API | FCM с телефона на Chromium может не дойти. Это измеряется, а не обещается |
| Tauri поверх веба | Отдельное окно и системный toast, пока процесс жив | На desktop своего push нет. Мобильный плагин снова FCM и APNs | Проект Rust, подпись Windows и нотаризация macOS, свой канал обновления, отдельное хранилище сессии | Не будит закрытое приложение и не решает карманный Android |
| Electron поверх веба | Окно Chromium и toast живого процесса | Push внутри Electron смотрит в FCM. Трей может опрашивать наш API | Тяжёлый установщик, подпись, свой автообновлятор, вечный процесс | Двойной клиент рядом с сайтом и та же зависимость Chrome от Google |
| Capacitor | Иконка магазина, нативный запрос разрешения | iOS через APNs, но уже после Apple Developer Program. Android штатно через FCM. Обход FCM только отдельным SDK RuStore | Два нативных проекта, консоли, ревью, версии бинарников мимо образа Next | Оболочка над сайтом может не пройти модерацию. Один публичный отчёт это уже показал. Штатный push Android проблему FCM не снимает |

Рекомендация. Делать PWA и письмо. Tauri рассматривать только если появится запрос на постоянно открытое настольное окно. Capacitor с RuStore рассматривать только если квитанции покажут устойчивую недоставку на хост FCM и письма окажется мало. Electron не заводить.

### 3. Три таблицы, не колонки профиля

`notification_settings` хранит одну строку на пользователя. В строке лежат оба включённых вида, пояс IANA, два часа, два канала, язык `ru` или `en` и `updated_at`. Первичный ключ `user_id`, внешний ключ на `user` с `ON DELETE CASCADE`. Строка появляется только при явном сохранении. Пояс по умолчанию сервер не подставляет. Форма предлагает пояс браузера, человек сохраняет его сам.

`push_subscriptions` хранит много строк на пользователя. Идентификатор UUIDv7. В строке лежат `endpoint`, `p256dh`, `auth`, необязательный `expiration`, усечённый `user_agent`, времена создания и отключения и счётчик неудач. Уникальность `(user_id, endpoint)`. Тот же cascade. Активных подписок не больше 10. Список для клиента отдаёт идентификатор и времена, без endpoint и ключей.

`notification_deliveries` фиксирует слот. Идентификатор UUIDv7. В строке лежат `user_id`, `kind` со значениями `due_digest` или `streak_warning`, `channel` со значениями `web_push` или `email`, `study_day` как текст `yyyy-mm-dd` по UTC, `status` со значениями `reserved`, `sent`, `skipped` или `failed`, `lease_until`, `error_code` и `push_service` со значениями `fcm`, `mozilla`, `apple` или `other`. Уникальность `(user_id, kind, channel, study_day)`. Endpoint в квитанцию не копируется. Cascade с пользователя удаляет и квитанции.

Дополнительных индексов сверх первичных ключей и этих уникальностей нет. Тик читает включённые настройки последовательным проходом. Это приемлемо, пока включивших немного. Отдельный индекс по часу понадобится только когда такой проход станет виден на `GET /ready` как занятый воркер. Сейчас его не заводить.

Колонки на `profile` не подходят. Снимок отмены перечисляет поля профиля. Новая колонка рядом с серией повышает шанс, что будущая правка снимка откатит час напоминания вместе с оценкой. Отдельная таблица этого соседства не создаёт.

### 4. Слот резервируется строкой, не сессионным замком

Пул соединений не держит `pg_advisory_lock` между запросами предсказуемо. Транзакционный замок нельзя держать на время HTTP к push-сервису. Поэтому гонку закрывает уникальный слот.

Тик раз в 60 секунд. Для каждой включённой настройки процесс через `Intl` находит `due_at`: первое мгновение текущего учебного дня UTC `[00:00Z, 24:00Z)`, когда местное время в сохранённом поясе достигает сохранённого часа `:00`. Повторённый зимним переходом час берётся в первое наступление. Пропущенный летним переходом час получает `due_at` в мгновение скачка. Если час внутри этого дня UTC не наступает и не перепрыгивается, отправки в этот день нет. Слот не трогается, пока текущее время раньше `due_at`. Пропущенный тик догоняется любым следующим проходом до конца того же учебного дня UTC, в том числе после местной полуночи. Если число доступных карточек нулевое, строка дайджеста не пишется, и день не сгорает. Число берётся из того же обзора, что `totalAvailable`.

Победитель вставляет `reserved` с `lease_until` на две минуты. Конфликт с уже `sent` ничего не делает. Просроченный `reserved` можно забрать одним условным `UPDATE ... RETURNING`. После принятия сообщения внешним сервисом статус становится `sent`. Если процесс умер в промежутке, следующая попытка допустима один раз. Это предел, записанный в спецификации.

`no_subscription` для push завершает слот на этот день. `email_unconfigured` не завершает день. Повтор идёт после короткой аренды в 15 минут, чтобы тик не молотил журнал каждую минуту и чтобы письмо ушло в тот же день, если ключ Resend появится.

Один сбойный пользователь не прерывает цикл. Коды ошибок машинные.

Воркер `reminder` регистрируется рядом с существующими. Снимок для `GET /ready` содержит глубину, активную работу, деградацию и код последней ошибки. Идентификаторов пользователей, endpoint и текстов нет. Drain в `createShutdownCoordinator` гасит таймер и дожидается текущих отправок в общем `SHUTDOWN_TIMEOUT_MS`. Новый тик после начала остановки не стартует.

В `NODE_ENV=test` тик сам не идёт. Тесты вызывают один проход с подставленными часами и почтовым двойником.

### 5. Два канала, одни и те же слова

Web Push. Переменные `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` и `VAPID_SUBJECT` необязательны. `VAPID_SUBJECT` равен `mailto:` или `https://app.reomi.ru`. Если ключей нет, `POST` подписки отвечает 503 `push_disabled`, интерфейс прячет включение push, а учёба работает. Библиотеку шифрования выбирать по тому, что она отправляет фикстуру под Bun на локальный приёмник. Свою реализацию AES-GCM не писать. Firebase не подключать. Тело JSON держать в пределах 3072 байт, чтобы с накладными расходами шифрования уложиться в лимит Apple 4 КБ.

Клиент по нажатию вызывает `pushManager.subscribe` с `userVisibleOnly: true` и публичным ключом. Подписка уходит на API сессией cookie. Service worker на `push` вызывает `showNotification`, затем `setAppBadge`, если метод есть. `notificationclick` фокусирует клиент или открывает `/review`.

Почта. Тот же текст уходит через `sendEmail` с меткой `notification`. Если провайдера нет, отправка пропускается, а процесс остаётся жив. Адрес берётся из аккаунта. Письмо не становится каналом сброса пароля и не меняет `EMAIL_FROM`.

Язык строки выбирает сохранённый `ru` или `en`. Словарь маленький и серверный, потому что worker не грузит словарь React и кэшировать его нельзя.

Ссылка строится от `WEB_ORIGIN`.

Журнал отправки может содержать идентификатор пользователя, вид, канал, машинный код и класс push-сервиса. Полный endpoint, ключи и тело сообщения в журнал не попадают.

### 6. Worker остаётся пустым кэшем

`globPublicPatterns: []` и `manifestTransforms`, который возвращает пустой манифест, не трогать. `defaultCache` и `runtimeCaching` не добавлять. Слушатели `push` и `notificationclick` ставятся рядом с `serwist.addEventListeners()`. Это не слой данных. Проверка на отсутствие кэша остаётся отдельным тестом, чтобы слушатель push не стал поводом включить precache.

В разработке worker выключен. Подсказку установки проверять на production-сборке, где worker есть.

### 7. Подсказка установки не модальная

Chromium. Поймать `beforeinstallprompt`, показать тихую кнопку, по отказу записать флаг через существующий помощник `reomi:` / `nn:`. Повторно не показывать.

iOS вне `standalone`. Показать шаги Share и Add to Home Screen тем же тихим блоком. Закрытие запоминается так же. Повторение доступно сразу.

`display-mode: standalone` прячет оба блока.

Запрос `Notification.requestPermission` остаётся только на жесте. Серверное включение push требует отдельного жеста. Оно не копирует старый локальный флаг в разрешение на письмо или push.

### 8. Экспорт и удаление

`GET /profile/export` добавляет объект настроек и не добавляет подписки. `DELETE /profile` уже удаляет пользователя. Внешние ключи с cascade забирают три новые таблицы. Отдельный проход по S3 для них не нужен.

Маршруты настроек и подписок требуют cookie-сессию. Personal access token их не пишет. Это не обход подтверждения ассистента и не новый инструмент MCP.

## Risks / Trade-offs

- [Chromium в РФ ходит на `fcm.googleapis.com`] → Письмо является настоящим каналом, а не спрятанной настройкой. Квитанция хранит класс сервиса. Решение о RuStore принимать по этой доле, не заранее.
- [Пользователь iOS не поставит иконку] → Шаги Home Screen видны, учёба не заперта, письмо работает без установки.
- [Браузер на компьютере полностью закрыт] → Web Push не придёт, письмо придёт, если канал включён. Документ web.dev описывает это ограничение для настольного Chrome.
- [Двойная отправка после гибели процесса] → Не больше одной повторной попытки слота. Обычный второй тик после `sent` молчит.
- [Два реплики API] → Уникальный слот, а не память процесса. Память остаётся у rate limit и cooldown, не у напоминаний.
- [Исходящий доступ Coolify режет `fcm.googleapis.com`, Mozilla или `*.push.apple.com`] → Push помечается неуспехом, письмо и учёба живы. Это проверить на staging до включения кнопки.
- [Локальный флаг уже включён у части людей] → Он по-прежнему только про уведомление при открытии. Серверные каналы выключены, пока человек их не сохранит.
- [Модерация магазина и подпись кода] → Не входят в этот change, поэтому не блокируют напоминание.
- [`next dev` без worker] → Установку и push проверять на сборке, где Serwist включён.

## Migration Plan

Правка схемы в `packages/db/src/schema/app.ts`, затем `bun run db:generate`. В коммит входит новый SQL следом за `0039_daily_ken_ellis.sql`. Применять `bun run db:migrate:apply` и в тестах `db:migrate:apply:test`. `drizzle-kit push --force` эту миграцию не заменяет.

Миграция только добавляет три таблицы, первичные ключи, две уникальности и внешние ключи `ON DELETE CASCADE` на `user`. Колонки старых таблиц не меняются. Обратного заполнения нет.

Порядок выкладки. Сначала образ API с таблицами и выключенным push, если переменные VAPID ещё пустые. Старый веб продолжает локальное уведомление при открытии. Затем веб с настройками, worker и подсказкой. Ключи VAPID и исходящий доступ включить до того, как кнопка push станет видимой.

Откат. Откат образа достаточен. Таблицы остаются. Старый API их не читает. Подписки не используются, пока новый код не вернётся. Удалять таблицы при откате не нужно. Повторный вперёд на тех же строках безопасен. Уникальный слот не даст второму успеху появиться заново для уже `sent` дня.

Индексы. Планировщик опирается на уникальность слота и уникальность endpoint. Отдельный индекс под тик не добавляется в этой миграции по причине из раздела про таблицы.

## Open Questions

Какая доля неуспешных push приходится на класс `fcm` у реальных сессий. Ответ пишется квитанциями и не меняет таблицы. От него зависит, заводить ли позже Android с RuStore Push.

Нужен ли Telegram как третий канал, если письма не открывают. Это новый бот и привязка аккаунта. В этот change он не входит.
