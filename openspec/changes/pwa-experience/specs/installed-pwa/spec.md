# Spec Delta

## Purpose

Сделать уже установленное веб-приложение способным показать серверное напоминание и объяснить установку там, где без неё push на iOS не существует.

## ADDED Requirements

### Requirement: Cache-free push worker
Production service worker SHALL оставаться зарегистрированным. Он MUST NOT класть ответы приложения в precache и MUST NOT вести runtime-кэш. Событие push SHALL заканчиваться видимым уведомлением. Если тело push не разбирается, worker SHALL всё равно показать общее уведомление без числа и без содержания учёбы. Нажатие уведомления SHALL сфокусировать уже открытое окно приложения или открыть маршрут повторения. Worker MUST NOT записывать данные учёбы в Cache Storage.

#### Scenario: Push arrives while the app is closed
- **WHEN** установленное приложение получает push дайджеста, а окна приложения нет
- **THEN** пользователь видит уведомление со числом доступных карточек

#### Scenario: Malformed payload
- **WHEN** событие push приходит без разбираемого тела
- **THEN** пользователь видит общее уведомление, а разрешение push не остаётся без показа

#### Scenario: Network still serves the app
- **WHEN** пользователь открывает установленное приложение после регистрации worker
- **THEN** документ и данные приходят из сети, а не из кэша worker

### Requirement: Install guidance
На браузере Chromium, который отдаёт `beforeinstallprompt`, приложение SHALL предложить установку из этого события и SHALL запомнить отказ в хранилище браузера. На iOS, пока режим показа не `standalone`, приложение SHALL показать шаги Share и затем Add to Home Screen. Подсказка MUST NOT блокировать повторение, вход и чтение. Режим `standalone` SHALL скрывать подсказку. Браузер без события установки и без этого разрыва iOS SHALL NOT показывать модальное окно установки.

Запрос разрешения на уведомления и вызов подписки push SHALL происходить только по явному действию пользователя.

#### Scenario: Dismissed install
- **WHEN** пользователь закрывает предложение установки Chromium
- **THEN** следующее открытие той же страницы не показывает его снова

#### Scenario: iOS browser tab
- **WHEN** человек открывает Reomi во вкладке на iOS и приложение не установлено на Home Screen
- **THEN** он видит шаги Share и Add to Home Screen и может перейти к повторению без установки

#### Scenario: Installed app
- **WHEN** приложение уже открыто в режиме `standalone`
- **THEN** подсказка установки скрыта

### Requirement: Badge follows platform support
Пока приложение открыто, бейдж SHALL по-прежнему отражать число доступных карточек там, где `setAppBadge` есть. Обработчик push SHALL выставить бейдж из числа в теле, если `setAppBadge` доступен в worker. Отсутствие Badging API MUST NOT отменять показ уведомления. Приложение MUST NOT обещать числовой бейдж на Chromium для Android. Там знак на иконке даёт само непрочитанное уведомление платформы.

#### Scenario: Open app on a capable desktop
- **WHEN** установленное приложение с Badging API открыто и число доступных карточек меняется
- **THEN** бейдж показывает это число

#### Scenario: Android without the API
- **WHEN** push приходит в установленное приложение, где `setAppBadge` нет
- **THEN** уведомление показано, а отсутствие бейджа не считается ошибкой доставки

### Requirement: Foreground notification stays local
Уведомление при открытии приложения SHALL по-прежнему требовать отдельное согласие и разрешение браузера. Оно SHALL срабатывать только пока открыт документ. Текст настроек SHALL называть его уведомлением при открытии. Текст MUST NOT называть его фоновым напоминанием.

#### Scenario: App closed
- **WHEN** согласие на уведомление при открытии включено, а ни одно окно приложения не открыто
- **THEN** это локальное уведомление не создаётся
